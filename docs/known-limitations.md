# 已知限制

按影响程度排序。未在真实环境逐项验证的功能一律保持“待验证”，不得当作已通过。

## L1. 登录结果的响应标记需要按你的门户校准

- 程序只按**显式标记**判断登录成功/失败；不认识响应时显示“认证结果未确认”，不会因为 HTTP 200 就报成功。
- 不同单位、不同门户版本的成功/失败页面文字可能不同，因此默认标记可能不完全适用。
- 处理方式：首次真实登录后，把门户实际返回的成功/失败提示补充到 `src/campuslink/auth/markers.py`；
  在完成校准前，请以“外网是否真的可用”和门户自助页面为准。
- 同一响应同时命中成功与失败标记、或 HTTP 4xx/5xx 时，程序统一判“未确认”。

## L2. 备用入口/备用路径需要本地确认

- `endpoints_local.py` 里可以配置多个入口和多个登录路径，但只有你本地验证过可达且页面结构一致的入口才应启用。
- 未验证的入口可能返回完全不同的页面；程序会拒绝提交并提示“协议不一致”。

## L3. 表单提交的字符编码

- 程序按页面声明的编码解码响应；但表单提交使用 HTTP 客户端默认的 UTF-8 百分号编码。
- 账号/密码通常是 ASCII，影响有限；若你的密码含非 ASCII 字符且登录失败，可能需要在传输层按页面编码构造请求体。

## L4. 注销结果可能需要二次确认

- 注销接口与成功标记因门户而异；无法确认时程序只显示“注销结果未确认”。
- 如果你关心计费，请到门户的自助服务页面确认是否真的下线。

## L5. 明文传输风险

- 部分校园网 Web 认证使用普通 HTTP 表单，密码在链路层可能以明文经过内网。
- Windows 凭据管理器只保护本地静态存储，不能消除协议本身的传输风险。
- 本项目不会通过关闭 TLS 校验、修改系统证书、关闭防火墙或配置全局代理来“解决”认证问题。

## L6. `netsh` 输出依赖系统语言

- Wi-Fi 名称探测解析 `netsh wlan show interfaces`，按字段名匹配，并对 UTF-8/GB18030 做了兜底。
- 极少见语言包下可能读不到 SSID；此时只影响“是否连着目标 Wi-Fi”的展示，不影响认证主流程。
- 多网卡/热点并存时，只要任一接口命中候选 SSID 即视为已连接。

## L7. 自动重连只能看到“逻辑掉线”

- 不监听链路层事件，而是按 `status_poll_interval_s`（默认 60s）做门户探测 + 联网探测，失败才使用指数退避。
- 掉线感知有一个探测周期的延迟；极端配置下恢复会变慢。
- 达到失败上限后会停手，手动登录成功或重新开关自动重连可恢复。

## L8. 未实现流量/余额查询

- 不做未经验证的页面解析，避免展示错误数据。

## L9. 单实例与开机自启的边界

- 未实现单实例互斥锁：重复启动会出现两个托盘图标。
- 开机自启写 `HKCU\...\Run`，只对当前用户、且在该用户登录后生效；不装服务、不建计划任务。
- 源码模式的自启命令会把 `src` 绝对路径写入命令，最稳妥的方式仍是使用打包后的 EXE。

## L10. 平台限制

- 仅面向 Windows 10/11；依赖 Windows 凭据管理器与 `netsh`，不支持 Linux/macOS。

## L11. 交付物签名与图标

- EXE 由 PyInstaller 单文件构建，带版本资源，但**未签名、无自定义图标**。
- Windows SmartScreen 可能提示“未知发布者”；企业安全软件可能对无签名单文件 EXE 更敏感。

## L12. 窗口子系统 EXE 的 CLI 输出不可见

- EXE 以无控制台方式构建；PowerShell 直接运行 `--check`/`--diagnostics` 时不会等待、也不显示文本。
- 脚本巡检请用源码方式运行，或使用 `cmd /c` / `Start-Process -Wait` 获取退出码。
